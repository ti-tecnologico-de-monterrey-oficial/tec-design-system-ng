## Solicitudes de carga de archivos

El tipo `BmbUploadFileMessage` forma parte de `BmbChatMessage` con el discriminante
`type: 'upload-file'`. Su renderer `BmbUploadFileMessageComponent` también se
exporta para uso independiente.

```typescript
const message: BmbUploadFileMessage = {
  id: 'upload-service-file',
  type: 'upload-file',
  timestamp: new Date(),
  isUser: false,
  content: {
    fileName: 'nombre de archivo de servicio',
    acceptedFormats: ['.pdf', '.doc', '.xml'],
    maxFileSize: 10,
    additionalRequirements: ['El documento debe ser legible.'],
  },
};
```

```html
<bmb-ai-chat-bubble
  [message]="message"
  [showActions]="false"
  (uploadFileRequested)="handleUploadRequest($event)"
/>
```

El evento `BmbUploadFileRequestEvent` contiene `messageId`, `message` y
`nativeEvent`. El componente abre su selector y valida los archivos mediante
`BmbChatAttachmentsService`. La aplicación consumidora realiza la subida real.
`filesSelected` emite solo los archivos aceptados; `attachmentResult` contiene
`sourceId`, `status`, `accepted` y `errors`. Una selección parcialmente válida
conserva los archivos aceptados y notifica los rechazados.

`maxFileSize` es un número expresado en MB; por ejemplo, `10` se muestra como
**10 MB**. Es opcional (2 MB por defecto), admite valores decimales y usa
1024 × 1024 bytes por MB. Se acepta el límite exacto. Los valores negativos,
infinitos o NaN son errores de configuración.

`acceptedFormats` valida su configuración al recibir o actualizar el mensaje:
cada elemento debe ser una extensión con punto inicial (`.pdf`, `.tar.gz`) o un
tipo MIME sin parámetros (`application/pdf`, `image/png`). También se admiten
`image/*`, `audio/*` y `video/*`. No se admiten espacios, listas separadas por
comas dentro de un elemento ni extensiones sin punto. Los valores inválidos
lanzan un error construido con `buildErrorMessage`. Esta validación verifica
la sintaxis, no la existencia de un subtipo MIME en un registro.
Los archivos se validan por extensión o MIME declarado, sin distinguir
mayúsculas. Una lista vacía o ausente permite cualquier formato. Esta
validación del navegador no sustituye la validación del servidor.

`text`, `buttonLabel` y `cancelKeyword` permiten personalizar los textos.
Los duplicados se identifican por nombre, tamaño y `lastModified`, tanto
dentro de una selección como contra los adjuntos actuales. El servicio no
lee ni transmite el contenido de los archivos.

### Una instancia por conversación

Proporciona `BmbChatAttachmentsService` en el componente contenedor de cada
conversación, no en la aplicación completa. La burbuja y la barra reutilizan
esa instancia. Fuera de un contenedor compartido, cada componente tiene
una instancia local y sigue funcionando de forma independiente.
`BmbAIChatCardComponent` no conecta ni gestiona archivos.
Al manejar manualmente los adjuntos de una burbuja independiente, llama a
`attachments.clear(message.id)` cuando consumas o descartes su borrador local.

```typescript
@Component({
  providers: [BmbChatAttachmentsService],
  template: `
    <bmb-ai-chat-bubble
      [message]="message"
      (attachmentResult)="handleSelection($event)"
      (retryUploadRequested)="retryUpload($event)"
    />
    <bmb-chat-bar (onSendFiles)="uploadFiles($event)" />
  `,
})
export class ConversationComponent {
  readonly attachments = inject(BmbChatAttachmentsService);
  // Define message y los manejadores de acuerdo con tu aplicación.
}
```

La barra registra su modelo `files` como borrador; `[(files)]`, `filesChange`
y `onSendFiles` mantienen sus contratos. Su selector y los archivos arrastrados
pasan por el mismo servicio, usando `acceptedExtensions` y `maxFileSize`.
Cuando una burbuja agrega archivos se respetan tanto sus límites como los de
la barra. Solo debe haber una barra por instancia; una selección con varias
barras devuelve el error `unavailable`, sin modificar sus borradores.
Los cambios externos directos a `files` siguen siendo responsabilidad de la
aplicación; la validación automática se ejecuta en las selecciones del usuario.

### Errores, éxito y reintento

Los errores `format`, `size` y `duplicate` muestran un aviso rojo con
instrucciones de recuperación. El botón **+** permite seleccionar otro archivo.
Para una subida interrumpida, usa
`attachments.reportUploadResult(message.id, { code: 'interrupted' })`
o establece `message.content.error` con ese valor. Se muestra un aviso amarillo
y **Reintentar carga**, que emite `retryUploadRequested` con el mensaje y el
evento nativo; no abre el selector ni sube automáticamente.

La aplicación debe conservar los archivos de `onSendFiles` para reintentarlos.
Después de enviar, la barra limpia el borrador y los avisos locales.
Una selección correcta tiene estado `selected`, no `uploaded`.
Solo tras confirmar la subida, llama a
`attachments.reportUploadResult(message.id)` para mostrar el éxito real.
Si se proporciona `content.error`, tiene prioridad sobre el estado del servicio:
la aplicación debe quitarlo o actualizarlo al resolver el error.

Los textos predeterminados usan el servicio de traducciones en español e inglés.
La instrucción de escribir **Cancelar** no cancela automáticamente la
conversación: la aplicación debe procesar esa respuesta desde la barra de chat.
